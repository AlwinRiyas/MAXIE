project. Nothing in it was edited, reformatted, or "fixed" — the only files
added are this one, `REVIEW_REPORT.md`, and `FILE_TREE.txt`.

Every omission is listed below so the reviewer knows exactly what they are not
looking at.

## Deliberate deviation: `Installers/` is **INCLUDED**

The instruction was to exclude "installers". `Installers/` was initially
excluded — **and it broke the test suite**, which is the evidence for
including it:

```
$ python Tests/run_tests.py        # with Installers/ removed
ERROR: test_autostart_targets_run_py (Tests.ui_test.UiModuleTest...)
  File "Ui/gui.py", line 16, in _load_autostart
    spec.loader.exec_module(module)
FileNotFoundError: [Errno 2] No such file or directory:
  '.../Installers/set_autostart.py'
Ran 138 tests
FAILED (errors=1, skipped=1)
```

`Tests/ui_test.py` loads `Installers/set_autostart.py` at test time, so the
suite cannot pass without it. The directory also holds only hand-written
Python source (306 LOC) that `AGENTS.md` documents as a first-class part of
the architecture — not installer binaries.

**Decision:** `Installers/set_autostart.py` and `Installers/setup_tts.py` are
included, because the package must contain a runnable test suite and because
they are source. This is recorded as bug **B2** in `REVIEW_REPORT.md` (a
coupling that should be fixed by moving the autostart logic out of
`Installers/` into a normal module).

## Generated during verification, then removed

Running the test suite inside a scratch copy created these files. They were
deleted from the package so it ships clean:

- `Memory/maxie_memory.db` (SQLite, created by memory tests)
- `Logs/maxie.log`
- `__pycache__/` directories

The three `Config/*.json` files are **rewritten on every load** by
`Config._load_file()` (bug **B9**) and were therefore touched by the test run.
They were verified **byte-identical** to the originals after the run, so the
packaged config is unmodified.

## Files in the package that are 0 bytes in the real project

These are **not** packaging errors — they are empty placeholders that exist
in MAXIE itself, listed so the reviewer sees the true state of the codebase
(also flagged in `REVIEW_REPORT.md` §5, §6):

- `WakeWord/__init__.py`, `wake_listener.py`, `wake_models.py`,
  `wake_word_engine.py` — the entire `WakeWord/` package is empty. The real
  implementation is `Voice/wake_word_engine.py` (4 lines).
- `Docs/API_REFERENCE.md`, `Docs/ARCHITECTURE.md`, `Docs/CHANGELOG.md`,
  `Docs/CODING_STANDARDS.md`, `Docs/ROADMAP.md` — 5 of 7 docs are empty.
  Only `Docs/MAXIE_PRINCIPLES.md` has content.
- `Config/voice_config.py` — empty duplicate; `Voice/voice_config.py` is live.
- All `__init__.py` files are empty, which matches the project's stated
  convention (no `__init__` logic).
- `Models/`, `Plugins/`, `Resourses/`, `Vision/` contain only an empty
  `__init__.py`.
- `Voice/Core/` is an empty directory and was dropped (it holds no files).
